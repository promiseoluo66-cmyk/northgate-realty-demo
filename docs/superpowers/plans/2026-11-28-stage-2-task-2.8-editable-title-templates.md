## Goal

Add a small built-in library of original, versioned title templates. Choosing a template creates an ordinary editable text clip using the existing project model, registered text operations, animation keyframes and MLT text renderer. A saved project must contain the resolved text/style/keyframe data and must not depend on the template library being present later.

## Approved design and safety boundaries

- Ship exactly four original built-in templates: Clean Centre Title, Editorial Lower Third, Bold Section Title and Animated Rise Title.
- Keep template definitions as data in `video-editor/title_templates.py`; do not load template files, HTML, JavaScript, SVG, fonts, images, network resources or executable code.
- A template record contains only `id`, `name`, `schema_version`, `text_defaults` and `animation_defaults`.
- Use a strict closed schema, schema version 1, stable unique IDs, unique case-insensitive names, bounded catalogue size and bounded text/animation fields.
- Animation keyframe times in templates use a normalized `time_ratio` from 0 to 1. Resolve them to clip-local integer microseconds using the requested clip duration. This keeps templates usable for different clip lengths.
- Keep animation limited to text-supported transform/opacity keyframes and existing interpolation rules. Reject unsupported properties, duplicate property/time pairs, non-finite values, and invalid combinations.
- Applying a template copies resolved values into a normal text clip. Do not store a live template reference or require a template ID during later rendering/reopening.
- Reuse `timeline.add_text_clip` with an optional `template_id`; merge explicit `text_style` overrides over validated template defaults. Reuse `text.update_clip` for subsequent edits.
- Add a read-only `title_templates.list` operation for the Studio/AI catalogue. It must not change project revision, history or saved project data.
- Never add user-uploaded templates, custom scripting, arbitrary asset loading, a separate renderer, paid providers or new runtime dependencies in this task.
- No Worker deployment, merge, release or production configuration changes.

## Acceptance criteria

- Four built-in templates are listed through a read-only operation.
- All template input/data is strictly validated and bounded; no executable or external content is accepted.
- Inserting a template creates a standard editable text clip whose style and keyframes are copied into the project.
- Existing `timeline.add_text_clip` callers without a template ID continue to work unchanged.
- Template insertion respects clip duration, track locking, project validation, revision checks, undo/redo and atomic rollback.
- Saved/reopened projects render without consulting the template library.
- Static and animated templates are verified using actual MLT-generated output frames, not only source-code assertions.
- The mobile UI can list, select and insert templates and then edit the inserted clip using the existing inspector.
- Relevant focused and full automated test suites pass with exact counts recorded.
- `main`, production deployment, unrelated repositories and gated/blocked Stage 2 tasks remain untouched.

## Explicit exclusions

No user-defined template save/import/export, template marketplace, arbitrary fonts/assets, template preview rendering service, animation editor redesign, caption feature changes, deployment, merge, release or Stage 3 work.
