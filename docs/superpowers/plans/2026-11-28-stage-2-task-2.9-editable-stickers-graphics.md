# Stage 2 Task 2.9 — Editable Stickers and Graphics

**Status:** Design approved; implementation plan awaiting user approval.  
**Repository:** promiseoluo66-cmyk/northgate-realty-demo  
**Branch:** video-editor-lab

## Goal

Add editable native graphic overlays and imported raster-image stickers. Preserve the canonical project model, authenticated private media lifecycle, revision-checked editing, undo/redo and MLT rendering. No AI, paid services, new dependencies, deployment or merge.

## Approved design decisions

1. Native graphics are editable overlay clips, not flattened video.
2. Initial native types: rectangle, ellipse, arrow and frame.
3. Imported stickers reuse the existing authenticated private image asset import/storage lifecycle. No duplicate upload system.
4. Support static PNG, JPEG and WebP only. Reject SVG, HTML, scripts, vector documents and animated GIF; never execute or interpret imported markup.
5. Geometry/style values are bounded and project-relative. Imported assets retain source filename and user-declared provenance/rights metadata. A declaration is not independent legal verification.
6. Native shapes use renderer-owned drawing primitives; images use the existing trusted decoder. No arbitrary markup is passed to a browser, shell, MLT expression or script engine.
7. No AI generation, external asset search, paid API, billing, runtime dependency, deployment or merge.

## Proposed project contract

- Native graphics are editable clips on an unlocked overlay track with a closed, versioned graphic data object.
- Validate type, normalized position/size, positive bounded dimensions, rotation, opacity, fill/stroke colours, stroke width, arrow endpoints and duration.
- Timing remains integer microseconds.
- Imported stickers reference an existing image asset ID. Never embed base64, data URLs, public URLs or signed URLs in project JSON.
- Add bounded provenance fields to image assets: original filename, optional creator/source, required user rights/licence declaration for sticker use, and import timestamp.
- Projects without graphics/provenance fields remain valid and render unchanged.

## Acceptance criteria

- [ ] Rectangle, ellipse, arrow and frame are editable and survive save/reopen.
- [ ] Static PNG/JPEG/WebP stickers reuse private assets and retain user-declared provenance.
- [ ] Unknown types/fields, malformed colours, non-finite/out-of-range geometry, invalid durations and invalid asset references are rejected.
- [ ] SVG/HTML/script/vector content and animated GIF are rejected.
- [ ] MIME, extension and signature agree; malformed files and dimension/pixel bombs are rejected.
- [ ] Failed imports and invalid edits do not partially mutate project, revision or history.
- [ ] Undo/redo works for create/update.
- [ ] Decoded MLT frames prove appearance, placement, opacity and timing boundaries.
- [ ] Older projects and existing workflows remain compatible.
- [ ] Full Python, Node/Worker and D1 checks pass with no new runtime dependency or paid service.
- [ ] Handoff, ledger and capability catalogue are read back and verified.

## Risks and exclusions

- Worker header validation cannot prove successful full decoding; renderer decoding is the second validation layer.
- User-declared rights metadata is not legal advice or independent verification.
- Offline CI does not prove live Worker upload or Android/browser acceptance.
- AI stickers (Task 2.10), the unresolved Task 2.4 authorization conflict and Stage 3 remain out of scope.
