## Goal

Make existing title and caption clips animatable while keeping their text and timing editable in the canonical project JSON. Reuse the current keyframe system and text renderer. Add word-by-word highlighting from verified timing data. Preserve static text as the safe fallback.

## Approved architecture

1. **One animation model.** Reuse existing clip-local keyframes and the existing `animation.set_keyframe` operation for properties already supported by the canonical keyframe model. Do not create a second animation engine or a duplicate text-edit operation.
2. **Text-specific presets are configuration, not a parallel engine.** Studio may offer bounded entrance, exit and loop presets. Presets must compile to the same canonical timing/keyframe representation. If a requested effect cannot be expressed safely by the existing model, stop and document the gap rather than silently adding a second model.
3. **Word highlighting uses verified word timing.** Reuse the existing transcript/caption word-timing contract wherever it can represent the required cue-to-word mapping. Add only the smallest optional, validated text-clip field or mapping if the current contract cannot associate words with a rendered caption. Do not invent timings or infer them from text.
4. **Renderer remains editable.** Compile animation at render time through the existing MLT/FFmpeg overlay path. Do not flatten the project text into a permanent video/image asset. Use ASS/libass karaoke timing only where the existing renderer supports it reliably; otherwise preserve static text and report the unsupported path.
5. **Safe fallback.** Missing, malformed, unsupported or out-of-range animation data must not corrupt the project or crash a render. The affected clip falls back to its existing static rendering, with a clear validation/UI error where appropriate.

### Step 2 — Write failing model and executor tests

Add tests first for:

- Older text clips with no animation fields remain valid and render statically.
- Supported text keyframe properties accept valid values and reject unknown properties, non-finite values and out-of-range values.
- Keyframe timestamps use the canonical clip-local microsecond timebase and cannot fall outside the clip.
- Entrance and exit timing at clip start/end, including zero-duration and very short clips.
- Loop intervals have positive duration, remain within the clip, and cannot create unbounded iteration or invalid frame counts.
- Word timing requires non-empty words, positive ranges, ordered/non-overlapping intervals, and bounds within the caption clip.
- Missing or incomplete word timing never fabricates highlight timing.
- Revision conflict, permission failure and invalid updates leave the project unchanged.

Run the focused tests and record the expected failures before implementation.

- Preserve project revision checks, confirmation metadata, atomic edits, undo and redo.
- Ensure invalid or unsupported animation changes are rejected before any project mutation.

### Step 4 — Implement render-time animation

- Render word highlighting from supplied verified timings using ASS karaoke tags or an equally supported renderer-native mechanism.
- Escape/quote text and generated filter expressions safely; never interpolate untrusted text directly into a shell command.
- Keep the unanimated text path unchanged.
- If a feature cannot be rendered correctly, render static text and surface a safe diagnostic rather than failing the whole project.
