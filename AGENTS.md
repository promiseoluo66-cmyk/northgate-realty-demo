# Repository Instructions for AI Coding Assistants

## Project scope

- The video-editor project is in `promiseoluo66-cmyk/northgate-realty-demo`.
- Work only on `video-editor-lab`. The `main` branch is the original Northgate Realty website and must remain untouched.
- Do not use or move this project to `sparkle-clean-co` or another repository.
- The user works from an Android phone and has no local development environment. Use connected GitHub tools; do not require a PC, terminal, VS Code, or Codespaces.
- Current budget is $0. Do not introduce paid services, billing activation, or hidden costs without explicit approval.

## Required process

- Inspect the repository, branch, current state, existing instructions, and prior decisions before changing files.
- For substantial work, obtain approval of the design before writing an implementation plan, then obtain approval of the exact plan before implementation.
- Use Context7 for current documentation when external APIs or platform behavior matter.
- Use test-driven development for code changes; verify tests and inspect their actual output.
- Use systematic debugging, then review architecture, research, implementation, debugging, testing, security, and final QA.
- Read files before updating them and preserve unrelated content and working features.
- Verify every created or updated document by reading it back from GitHub.

## Agent capability honesty

The current environment does not provide a genuine independent AI-agent runtime. Specialist responsibilities are review perspectives performed by the same ChatGPT session. Never claim separate agents were launched. GitHub Actions is a CI runner, not an AI agent system. Do not add agent configuration files unless a real supported consumer is verified.

## Safety and approval

- Never place credentials, tokens, or secrets in source files, documentation, or logs.
- Do not merge, deploy, publish releases, send messages, or perform destructive/irreversible actions without explicit user permission.
- Do not trigger GitHub Actions unnecessarily. Do not use the Sparkle Clean repository's Actions allowance; it is treated as exhausted for this month.
- Historical CI results are not fresh verification of new changes. Report exactly what was and was not tested.
- Preserve existing features and avoid duplicate implementations.
- Do not begin Stage 2 Task 2.4 (measured silence candidates with human review) unless the user explicitly authorises it.
